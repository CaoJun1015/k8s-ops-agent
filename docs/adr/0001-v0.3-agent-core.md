# ADR-0001: v0.3 Agent Core

状态：Accepted  
日期：2026-09-04

## 决策

v0.3 将 `AgentRun` 定义为围绕一个 Incident 执行的、有界的 L2 自主只读调查。
目标资源由 Incident 冻结为运行快照；调用方只可设置自然语言目标和受上限约束的预算。

循环协议只有四种结构化决策：

- `CALL_TOOL`：调用注册表中的一个只读工具，保存 ToolInvocation 和 Evidence 后继续。
- `COMPLETE`：提交符合诊断 Schema、且引用本次运行 Evidence 的最终结论。
- `ASK_HUMAN`：证据不足或策略要求接管，创建 Action Task 并结束自动循环。
- `STOP`：预算、重复调用、取消或明确安全原因导致停止。

默认预算为 8 步、6 次工具调用、单工具 15 秒、整体 120 秒、4 次模型调用和
20,000 个总 token；API 上限分别为 16、12、30 秒、300 秒、8 和 100,000。
相同工具和规范化参数最多调用一次。

规则推理器始终可用且是默认实现。启用 `rules+openai` 时，模型只返回严格 JSON；
超时、Schema 错误、伪造 Evidence、未知工具或 token 超限均审计并回退规则。

## 持久化与审计

- AgentStep 保存上下文快照、决策类型、简短摘要、来源、置信度和 Evidence 引用。
- ToolInvocation 保存工具版本、脱敏参数、状态、尝试次数、耗时和 Evidence 引用。
- Evidence 保存脱敏、限长后的外部事实；Audit 保存状态和安全决策。
- 不保存隐藏思维链、原始认证头、Secret 或完整模型响应。

## 安全边界

- Agent 只能看到 Tool Registry，不能得到 Kubernetes 客户端。
- v0.3 注册表只接受 `read_only=true` 工具，并由确定性策略再次检查集群、namespace、
  Incident 目标、UID、预算和重复调用。
- 禁止 Shell、kubectl、任意代码、任意 PromQL 和所有 Kubernetes 写 API。
- Agent Worker 使用只读 ServiceAccount；修复执行继续由独立 Execution Worker 承担。
- Agent Core 不进入自动修复路径，`AUTO_REMEDIATE_ENABLED` 保持关闭。

## 终态语义与回退

`COMPLETED` 表示得到有证据支持的结论；`AWAITING_HUMAN` 表示已创建人工任务；
`STOPPED` 表示受控停止；`FAILED` 表示不可安全降级的内部失败；`CANCELLED` 表示用户
取消。除完成外，Incident 转为可重新诊断的 `FAILED`。

`AGENT_CORE_ENABLED=false` 时沿用 v0.2 的固定 EvidenceCollector 和诊断路径。数据库
回滚只在已备份或可丢弃环境执行，因为 downgrade 会删除 v0.3 步骤和调用记录。
