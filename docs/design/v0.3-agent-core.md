# K8s Ops Agent v0.3：Agent Core 运行与安全指南

## 架构与数据流

```text
Incident API
  → AgentRun + Outbox（同一事务）
  → Agent RQ Worker（只读 ServiceAccount）
  → ContextBuilder → Rule/OpenAI Reasoner → NextDecision
  → Policy Gate → Tool Registry → Kubernetes/Prometheus Adapter
  → AgentStep + ToolInvocation + Evidence + Audit
  → COMPLETE / AWAITING_HUMAN / STOPPED / FAILED / CANCELLED
```

Agent Core 的自主等级固定为 L2，只能选择注册的只读调查工具。Plan、审批和 Execution
仍是独立工作流；Agent Core 不生成命令，也不会调用修复执行。

## 配置

| 配置 | 默认值 | 说明 |
|---|---|---|
| `AGENT_CORE_ENABLED` | `true` | 设为 `false` 回到 v0.2 固定采集诊断 |
| `AGENT_REASONER_PROVIDER` | `rules` | `rules` 或 `rules+openai` |
| `OPENAI_MODEL` | `gpt-5.4-mini` | 仅模型路径使用 |
| `OPENAI_API_KEY` | 空 | 规则路径不需要 |
| `ALLOWED_NAMESPACES` | `default` | Agent 工具允许读取的命名空间 |
| `AUTO_REMEDIATE_ENABLED` | `false` | v0.3 必须保持关闭 |

创建运行时可在 API 请求的 `budget` 中降低或调整预算，但不能超过服务端上限。默认值：
8 步、6 次工具调用、120 秒总时限、15 秒单工具时限、4 次模型调用和 20,000 token。

## Tool Registry 扩展

新工具必须以 `ToolDefinition` 注册，提供名称、版本、输入/输出 JSON Schema、超时、
集群和 namespace 范围。注册表拒绝 `read_only=false`；参数在 Adapter 调用前验证，结果
在持久化前脱敏和限长。禁止把 Kubernetes Client、任意 PromQL、Shell 或 kubectl 暴露
给 Reasoner。

新增只读工具时必须同时提供：Schema 单元测试、权限/范围测试、超时和安全错误测试、
EvidenceType 映射，以及 RBAC 不扩权证明。

## 运行、取消与人工接管

```bash
curl -X POST http://localhost/api/incidents/INCIDENT_ID/agent-runs \
  -H 'Content-Type: application/json' \
  -H 'Idempotency-Key: diagnose-INCIDENT_ID-1' \
  -d '{"goal":"定位根因","budget":{"max_steps":8,"max_tool_calls":6}}'

curl http://localhost/api/agent-runs/RUN_ID
curl http://localhost/api/agent-runs/RUN_ID/steps
curl http://localhost/api/agent-runs/RUN_ID/evidence
curl -X POST http://localhost/api/agent-runs/RUN_ID/cancel
```

取消是幂等的。正在执行的只读请求允许结束并保存事实，但不会开始下一步。工具超时、证据
不足或策略要求人工确认时会创建与 AgentRun 关联的 Action Task。

## 观测与排障

- `/metrics` 提供运行成功率、耗时、步骤、工具失败、预算停止和人工接管指标。
- `GET /api/audit-events?entity_type=AgentRun&entity_id=RUN_ID` 串联完整决策事实。
- UI 时间线区分规则/模型决策、工具事实和 Evidence，不展示上下文快照或完整敏感日志。
- Worker 中断后，Dispatcher 的恢复循环会终止过期运行并创建人工确认 Task。

## 本地与 kind 验证

Windows 工作区应从 Ubuntu WSL 执行：

```bash
cd /mnt/c/Users/cj/Desktop/k8s-ops-agent
bash ci/kind-e2e.sh
```

脚本只把 Git 可见的构建文件复制到 WSL 临时目录，绕过 DrvFS 缓存 ACL；依赖镜像通过
宿主 Docker 拉取并预载 kind。失败时输出 Pod、Event 和容器日志，默认始终清理专用
`ops-agent-e2e` 集群。

12 类离线评估由 `app/evals/scenarios.json` 定义，规则路径的确定性观测记录在
`app/evals/observations.rules.json`。运行 `python -m pytest app/tests/test_agent_evaluation.py -q`
可输出并校验成功率、平均步骤数和错误分类；真实 OpenAI API 不属于验收依赖。

## 回退

1. 设置 `AGENT_CORE_ENABLED=false` 并滚动重启 API 和 Agent Worker。
2. 创建新的 DIAGNOSE_ONLY 运行，确认进入 v0.2 的 COLLECTING/DIAGNOSING 路径。
3. 保留 v0.3 表即可完成应用回退；不会影响旧数据读取。
4. 只有在完成备份或可丢弃数据库中才执行 `alembic downgrade 0005_incident_source_context`，
   因为该操作会删除 AgentStep 与 ToolInvocation。

`ci/kind-e2e.sh` 会在可丢弃的 kind PostgreSQL 中自动演练功能开关回退，以及
`0006 → 0005 → 0006` 的数据库降级和重新升级。

## 明确禁止

- 不允许 Agent 执行 Shell、kubectl、代码、Pod 删除或其他集群写操作。
- 不允许模型扩大 ToolDefinition、namespace 或资源目标。
- 不保存隐藏思维链、Token、Cookie、Authorization、kubeconfig 或真实 Secret。
- 不将模拟结果描述为真实 Kubernetes、PostgreSQL、Redis 或 Prometheus 验证。
