# K8s Ops Agent v0.3：Agent Core 任务卡片

> 文档状态：待评审  
> 版本目标：把固定诊断工作流升级为受控、可审计、可迭代的单 Agent 诊断循环  
> 安全边界：v0.3 只允许自主调用只读工具，不允许 Agent 修改 Kubernetes 集群  
> 使用方式：按卡片依赖顺序实施；每完成一张卡，填写状态、验证记录和关联提交

## 1. v0.3 目标

v0.3 要让 Agent 能够围绕 Incident 自主完成以下循环：

```text
理解目标
  → 评估当前证据
  → 选择一个只读工具
  → 保存工具结果为 Evidence
  → 根据新证据继续调查或形成结论
  → 请求人工帮助或安全结束
```

本版本完成后，Agent 不再固定采集所有证据，而是能够根据 Incident 状态决定下一步
需要查询 Pod、日志、事件、工作负载还是 Prometheus。

## 2. 已确定的设计原则

- 采用单 Agent，不做多 Agent 协作。
- 保留现有 Incident、Task、Plan、Execution、Evidence、Outbox 和 Audit。
- 扩展 AgentRun，不推翻现有领域模型。
- Agent 的所有外部能力必须通过 Tool Registry 调用。
- v0.3 工具必须全部只读。
- 不允许执行任意 Shell、任意 kubectl 或模型生成的代码。
- LLM 只能返回符合 JSON Schema 的结构化决策。
- 不保存模型隐藏思维链，只保存可审计的决策摘要和证据引用。
- 每次运行都有步数、时间、工具调用和 Token/费用预算。
- 证据不足、策略拒绝、预算耗尽或连续失败时必须安全停止。
- 可选 LLM 失败时，系统必须能够降级到规则诊断。
- v0.3 不引入向量数据库，不开放自动修复。

### ADR-01：确认 Agent Core 架构决策

| 属性 | 内容 |
|---|---|
| 状态 | 待开始 |
| 优先级 | P0 |
| 预估 | 0.5～1 天 |
| 依赖 | PRE-01 |

**目标**

形成一份简短 ADR，冻结 v0.3 的 Agent 定义、循环协议、自主等级和安全边界。

**必须确定**

- AgentRun 的目标表达方式。
- `NextDecision` 的允许类型。
- Agent 最大步数、最大运行时间和最大工具调用数。
- 规则与 LLM 的优先级和降级关系。
- `COMPLETE`、`ASK_HUMAN`、`STOPPED`、`FAILED` 的语义。
- AgentStep、Evidence、Audit 各自保存什么。
- 不保存完整思维链的审计方案。
- v0.3 自主等级固定为 L2：自主只读调查。

**建议决策类型**

```text
CALL_TOOL
COMPLETE
ASK_HUMAN
STOP
```

**验收标准**

- [ ] ADR 获得确认并进入仓库。
- [ ] 每种决策都有输入、输出和失败语义。
- [ ] 明确禁止 Shell、写工具和无界循环。
- [ ] 后续任务不需要重新猜测 Agent 的边界。

### TOOL-01：实现 Tool Registry 和统一工具协议

| 属性 | 内容 |
|---|---|
| 状态 | 待开始 |
| 优先级 | P0 |
| 预估 | 1～2 天 |
| 依赖 | ADR-01、DATA-01 |

**目标**

将 Agent 可以使用的能力注册为有 Schema、有风险等级、有超时的显式工具。

**ToolDefinition 必须包含**

- 名称和版本。
- 人类可读描述。
- JSON 输入 Schema。
- JSON 输出 Schema。
- `read_only`。
- `risk_level`。
- `requires_approval`。
- 超时时间。
- 允许的集群和 namespace 范围。

**协议要求**

- 工具名称只能来自注册表。
- 参数必须先通过 Schema 校验。
- 工具返回结构化结果，不直接返回客户端对象。
- 工具结果必须经过脱敏和限长后保存为 Evidence。
- 工具异常统一转换为安全错误类型。
- Agent 不能获得 Kubernetes 客户端实例。

**验收标准**

- [ ] 未注册工具无法调用。
- [ ] 非法参数在调用 Adapter 前被拒绝。
- [ ] v0.3 注册表拒绝所有 `read_only=false` 工具。
- [ ] 工具调用产生 ToolInvocation、Evidence 和 Audit。
- [ ] Schema、权限、超时和错误转换测试完成。

### CTX-01：实现 AgentContextBuilder

| 属性 | 内容 |
|---|---|
| 状态 | 待开始 |
| 优先级 | P0 |
| 预估 | 1～2 天 |
| 依赖 | DATA-01、TOOL-02 |

**目标**

为每一步决策生成最小、结构化、可复现的 Agent 上下文。

**上下文内容**

- AgentRun 目标和自主等级。
- Incident 摘要、目标资源和当前状态。
- 已有 Evidence 摘要与 Evidence ID。
- 已调用工具、参数摘要和结果状态。

- 不把完整日志和事件无限制拼入 Prompt。

**验收标准**

- [ ] 上下文大小有硬限制。
- [ ] Secret、Token、Cookie 和认证头被脱敏。
- [ ] 工具结果中的提示注入文本不能改变系统约束。
- [ ] 可根据保存的快照复现模型输入结构。

### REASON-01：实现结构化 NextDecision

| 属性 | 内容 |
|---|---|
| 状态 | 待开始 |
| 优先级 | P0 |
| 预估 | 2～3 天 |
| 依赖 | ADR-01、CTX-01、TOOL-01 |

**目标**

让规则或可选 LLM 返回严格的下一步决策，而不是自由文本或命令。

**建议结构**

```json
{
  "decision_type": "CALL_TOOL|COMPLETE|ASK_HUMAN|STOP",
  "tool_name": "string|null",
  "arguments": {},
  "decision_summary": "string",
  "evidence_ids": ["uuid"],
  "confidence": 0.0,
  "stop_reason": "string|null"
}
```

**要求**

- 使用固定 JSON Schema。
- `tool_name` 必须来自当前 Tool Registry。
- 决策只能引用本次 AgentRun 可见的 Evidence ID。
- 不允许在字段中嵌入 Shell、kubectl 或可执行代码。
- LLM 超时、非法 JSON、Schema 错误时回退到规则策略。
- 保存模型、Prompt 和 Schema 版本，不保存完整隐藏思维链。

**验收标准**

- [ ] 合法决策可以稳定解析。
- [ ] 未注册工具、伪造 Evidence ID 和多余字段被拒绝。
- [ ] 日志中的提示注入不能越过决策 Schema。
- [ ] LLM 不可用时规则路径仍可完成基本诊断。
- [ ] 所有失败均形成安全 Audit。

### LOOP-01：实现有界 Agent Orchestrator

| 属性 | 内容 |
|---|---|
| 状态 | 待开始 |
| 优先级 | P0 |
| 预估 | 3～4 天 |
| 依赖 | DATA-01、TOOL-01、CTX-01、REASON-01 |

**目标**

实现 `评估 → 调用工具 → 保存证据 → 再评估 → 安全结束` 的 Agent 主循环。

**循环能力**

- 创建连续编号的 AgentStep。
- 每一步重新构建上下文。
- 调用 Reasoner 获得 NextDecision。
- 在策略允许后调用一个只读工具。
- 将工具结果持久化为 Evidence。
- 根据新证据继续、完成、请求人工或停止。
- 支持用户取消和 Worker 中断。

**默认预算建议**

| 预算 | 默认值 |
|---|---:|
| 最大步骤 | 8 |
| 最大工具调用 | 6 |
| 单工具超时 | 15 秒 |
| 整体运行时间 | 120 秒 |
| 相同工具+参数重复次数 | 1 |

**验收标准**

- [ ] Agent 可以根据第一次结果选择第二个不同工具。
- [ ] 达到最大步数后进入明确停止状态。
- [ ] 不会无限重复相同工具和参数。
- [ ] 每一步事务状态一致，进程异常后可恢复或安全失败。
- [ ] `COMPLETE` 必须引用足够 Evidence。
- [ ] v0.3 循环无法进入任何写工具。

### POLICY-01：增加 Agent 工具策略闸门

| 属性 | 内容 |
|---|---|
| 状态 | 待开始 |
| 优先级 | P0 |
| 预估 | 1～2 天 |
| 依赖 | TOOL-01、LOOP-01 |

**目标**

保证每次工具调用都由确定性策略决定是否允许，模型不能自行扩大权限。

**策略检查**

- Agent 自主等级。
- 工具是否只读。
- 集群和 namespace 是否允许。
- 目标资源是否属于当前 Incident。
- 参数是否经过 Schema 校验。
- 调用预算是否充足。
- 是否重复调用。
- 是否命中禁止资源或系统命名空间。

**验收标准**

- [ ] 策略结果只有 ALLOW、DENY、ASK_HUMAN。
- [ ] 所有 DENY 都记录机器可读原因码。
- [ ] 模型无法修改 ToolDefinition 或策略输入。
- [ ] 策略拒绝不会被自动重试绕过。
- [ ] v0.3 中写工具始终为 DENY。

### REL-01：完善失败、重试、取消和停止语义

| 属性 | 内容 |
|---|---|
| 状态 | 待开始 |
| 优先级 | P1 |
| 预估 | 2 天 |
| 依赖 | LOOP-01、POLICY-01 |

**目标**

让 Agent 在工具、模型、网络、队列或数据库异常时可预测地停止和恢复。

**工作范围**

- 区分可重试读取错误与不可重试错误。

- Worker 重启后不重复已经成功的工具调用。

- 增加 `stop_reason` 和标准错误码。
- 超时后创建人工调查 Task。

**验收标准**

- [ ] 模型超时不会丢失已保存 Evidence。
- [ ] 工具超时不会生成重复 ToolInvocation。
- [ ] Worker 中断后最终状态不是永久 RUNNING。
- [ ] 用户取消后不再启动新步骤。
- [ ] 所有停止路径都有 Audit 和可读原因。

### EVAL-01：建立 Agent 决策评估集

| 属性 | 内容 |
|---|---|
| 状态 | 待开始 |
| 优先级 | P0 |
| 预估 | 3～4 天 |
| 依赖 | REASON-01、LOOP-01、POLICY-01 |

**目标**

测试 Agent 的调查决策是否正确，而不只测试 API 是否返回成功。

**首批场景**

- CrashLoopBackOff。
- OOMKilled。
- ImagePullBackOff。
- Pod Pending。
- Readiness Probe 失败。
- Redis 不可用。
- Deployment 副本不足。
- CPU/内存高。
- 5xx 错误率升高。
- 证据不足、无法判断根因。
- 日志中包含提示注入文本。
- Kubernetes 或 Prometheus 工具超时。

**每个场景至少断言**

- 允许调用的工具集合。
- 禁止调用的工具集合。
- 必须引用的 Evidence 类型。
- 最大步骤数。
- 合理的完成或人工接管结果。
- 绝不允许产生集群写操作。

**验收标准**

- [ ] 规则路径可以完全离线、确定性运行。
- [ ] LLM 路径可以使用录制响应或可控测试适配器。
- [ ] 提示注入场景无法改变系统边界。
- [ ] 评估输出包含成功率、平均步骤数和错误分类。

### E2E-01：在 kind 中验证只读 Agent 闭环

| 属性 | 内容 |
|---|---|
| 状态 | 待开始 |
| 优先级 | P0 |
| 预估 | 2～3 天 |
| 依赖 | QUEUE-01、EVAL-01、OBS-01 |

**目标**

在真实 Kubernetes API、PostgreSQL、Redis 和 RQ Worker 上验证多步只读 Agent。

**E2E 场景**

```text
demo-app 发生 CrashLoopBackOff
  → Alert/Incident
  → AgentRun
  → CALL_TOOL:get_pod_status
  → CALL_TOOL:get_previous_logs
  → CALL_TOOL:get_kubernetes_events
  → COMPLETE:CRASH_LOOP
  → Evidence、AgentStep、ToolInvocation、Audit 可查询
```

**验收标准**

- [ ] Agent 根据证据按需选择至少两个不同工具。
- [ ] 所有工具结果来自真实 Kubernetes API。
- [ ] 每一步在数据库中可追踪。
- [ ] 最终结论引用真实 Evidence ID。
- [ ] Agent 使用的 ServiceAccount 没有写资源权限。
- [ ] 达到完成条件后不会继续调用工具。
- [ ] 集群结束后临时资源可安全清理。

**非目标**

- 不执行 Pod 重建。
- 不验证自动修复。

## 5. v0.3 Definition of Done

只有同时满足以下条件，v0.3 才算完成：

- [ ] Agent 能围绕一个 Incident 连续执行至少两步不同的只读工具调用。
- [ ] Agent 能根据新 Evidence 改变下一步决策。
- [ ] 每次决策、工具调用、Evidence 和停止原因均可审计。
- [ ] 所有模型输出都经过严格 Schema 校验。
- [ ] Agent 无法调用未注册工具或写 Kubernetes API。
- [ ] 达到步数、时间、调用或费用预算时能够安全停止。
- [ ] 工具或模型失败时能够降级、人工接管或明确失败。
- [ ] 现有 v0.2 固定规则诊断仍可通过功能开关使用。
- [ ] 单元、集成、评估和 kind E2E 全部通过。
- [ ] 自动修复仍保持关闭。
- [ ] 运行与回滚文档完整。
