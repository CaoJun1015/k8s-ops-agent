# 上下文记忆窗口与 Agent / LLM 决策任务卡

> 文档状态：已完成（2026-09-10）  
> 基线：现有 v0.3 单 Agent 只读调查循环  
> 目标：让每轮决策获得预算内、可追溯且不过时的上下文，并明确模型调用与降级边界  
> 交付方式：代码与文档已写入工作区，尚未创建 Git 提交。验证详情见 [验收记录](context-memory-verification.md)。

## 1. 范围与现状

复用 `AgentOrchestrator → AgentContextBuilder → Reasoner → AgentPolicy → ToolRegistry`。
Agent 在异步 Worker 中管理整个调查循环；LLM 仅在上下文构建后提出一个结构化决策。
工具执行结果保存为 Evidence 后，重新构建下一轮上下文。修复计划、审批、执行保持独立。

实施前核实的改造入口（以下问题已在本次实现中处理）：

- `app/ops_agent/agent_core.py`：上下文目前限制为 64 KiB，单条证据为 2 KiB；整体超限时删除所有证据正文，只留下截断标记。
- 同文件：模型输入按 UTF-8 字节数除以 4 估算，调用前只预留 256 token，而模型输出上限为 1,000 token。
- 同文件：决策引用校验目前使用本次运行的全部 Evidence ID，未区分本轮模型实际看到的证据。
- `FallbackReasoner`：主决策器异常才回退规则；外层决策校验失败当前进入失败路径，需要统一降级语义。
- `app/ops_agent/models.py`：已有运行、步骤、上下文快照、证据及采集时间，可复用作为记忆与审计来源。

本期不增加多 Agent、向量数据库、独立记忆服务、自动修复、跨运行对话恢复或用于摘要的额外模型调用。
默认继续使用规则；`rules+openai` 保持模型优先、失败回退规则的既有配置含义。
“规则先判断、复杂问题才调用 LLM”另列后续任务，避免修改现有配置语义。

## 2. 上下文契约

| 内容 | 处理方式 |
|---|---|
| 安全约束、目标范围、工具 Schema | 每轮保留，服务端独立校验，不允许裁剪后扩大权限 |
| 当前目标、资源 UID、预算 | 每轮保留，来源为服务端状态 |
| 工作摘要 | 区分事实、假设、失败尝试与信息缺口；事实必须引用证据 |
| 相关证据与最近步骤 | 按优先级装入窗口，记录省略与截断原因 |
| 历史案例 | 本期不加载 |

```text
本轮输入预算 = min(
    模型窗口 - 输出预留 - 安全余量,
    运行剩余 token - 输出预留 - 安全余量,
    应用单轮输入上限
)
```

预算覆盖实际发送的 instructions、上下文、工具定义和输出格式 Schema 等请求内容。
模型窗口大小由服务端配置，不使用未经核实的模型默认值。字节限制继续作为内存和存储保护。
估算值与提供方实际 usage 分开记录；估算不能描述为严格的计费上限保证。

## 4. 任务卡

### MEM-01：定义并构建运行内工作记忆

| 属性 | 内容 |
|---|---|
| 状态 | 已完成 |
| 优先级 | P0 |
| 依赖 | 无 |
| 主要位置 | `app/ops_agent/agent_core.py`、`app/ops_agent/models.py`（核查已有字段） |

**工作范围**

- 在上下文中定义带版本的 `working_memory`，包含 `confirmed`、`hypotheses`、`failed_attempts`、`missing`。
- 第一版从已持久化 Evidence、AgentStep、ToolInvocation 确定性重建；随现有 AgentStep 上下文快照保存，不新增记忆表或模型调用。
- 只把可直接读取的结构化观测写入事实；模型决策摘要作为假设或历史决策，不能自动升级为已确认事实。
- 事实带证据 ID；证据增加上下文元数据：采集时间、来源、所属运行、已知目标 UID、是否截断、是否过时。
- 按证据类型配置有效期，明确时间比较基准；时间缺失、UID 缺失标为未知，不能伪造。优先从已有证据内容和运行目标读取 UID。
- 仅处理当前运行；旧 UID 的证据标为历史，不作为新 Pod 当前状态的证明。沿用既有 UID 策略，不静默切换目标。

**验收标准**

- [x] 从相同持久化记录和同一时间基准重建，得到相同摘要。
- [x] 每条已确认事实均能定位原始 Evidence；不存在引用跨运行证据的情况。
- [x] 同名不同 UID、过期、时间缺失和未知 UID 的证据被正确区分。
- [x] 脱敏后内容进入摘要；日志中的指令保留为不可信数据，不能成为系统约束。
- [x] 空证据与旧步骤快照可读取；不需要数据库迁移。

### CTX-02：统一调用前 token 预算

| 属性 | 内容 |
|---|---|
| 状态 | 已完成 |
| 优先级 | P0 |
| 依赖 | MEM-01 |
| 主要位置 | `app/ops_agent/agent_core.py`、现有模型配置入口 |

**工作范围**

- 按上下文契约计算单轮预算，统一输出预留与实际 `max_output_tokens`，移除 256 与 1,000 不一致的约束。
- 计数对象与真实发送内容一致；优先复用现有可用 tokenizer，无匹配实现时使用明确标注的保守估算及安全余量，不能继续将字节除以 4 当作通用保证。
- 未知模型窗口配置无效时，在调用前拒绝模型路径并使用规则降级；不影响纯规则运行。
- 调用开始即记录模型尝试次数；无效响应和降级也保留已返回的 usage。超时且 usage 不可得时记录未知消耗并保守占用预留预算，禁止记作免费调用。
- 固定内容已超预算时，不发出模型请求；规则能继续则降级，否则受控停止并记录原因。

**验收标准**

- [x] 中文日志、英文日志、较大工具 Schema、边界预算和非正预算有可运行检查。
- [x] 每次实际模型请求均满足采用的计数或估算方式下的输入加输出预留约束。
- [x] 模型尝试失败、解析失败、usage 缺失不会获得额外免费重试额度。
- [x] 实际 usage 超出预算时保存已知消耗，停止后续模型调用及该决策的工具执行。
- [x] 规则模式不依赖模型窗口配置或模型 token 计数工具。

### CTX-03：实现按优先级裁剪的上下文窗口

| 属性 | 内容 |
|---|---|
| 状态 | 已完成 |
| 优先级 | P0 |
| 依赖 | MEM-01、CTX-02 |
| 主要位置 | `AgentContextBuilder`、现有证据脱敏逻辑 |

**工作范围**

- 保留固定约束、当前任务与有界工作摘要；证据按当前目标匹配度、有效性和采集时间稳定排序。
- 优先保留最新工具结果、结构化异常、当前假设引用的证据；已识别的相互矛盾观测都保留，无法同时装入时明确标为证据不完整。
- 日志使用有界片段；省略重复、无关和较旧正文，不再整体删除所有证据正文。
- 记录 `visible_evidence_ids`、省略数量、截断原因与选择策略版本。仅有 ID 占位符的证据不算可支撑结论的可见内容。
- 保留字节硬上限；裁剪后重新计数，不能通过截断 JSON 字符串制造无效上下文。
- 摘要与证据引用一致：删除证据正文时保留足够的事实摘要及来源，否则同步删除依赖它的事实。

**验收标准**

- [x] 大量无关日志下，关键异常事实和最新工具结果仍在窗口内。
- [x] 相同输入与预算产生稳定内容和哈希。
- [x] 极小预算不能通过删除安全约束、工具 Schema 或目标范围强行发起调用。
- [x] 已知冲突证据不会被悄然裁成单一结论；上下文明确标注不完整状态。
- [x] 所有输出都是可解析、已脱敏、满足字节上限的结构化对象。

### LOOP-02：接通记忆、决策校验与规则降级

| 属性 | 内容 |
|---|---|
| 状态 | 已完成 |
| 优先级 | P0 |
| 依赖 | CTX-03 |
| 主要位置 | `AgentOrchestrator`、`FallbackReasoner`、`validate_next_decision` |

**工作范围**

- 每轮先加载持久化记录，再构建工作记忆和预算内上下文，随后调用 Reasoner；工具结果提交后才进入下一轮。
- 模型引用只允许本轮实际可见证据；规则决策按其真实读取的本次运行证据集合校验，避免用模型裁剪窗口误伤规则。
- 统一模型超时、响应解析错误、Schema 错误及非法引用的降级入口。每步最多一次模型尝试和一次规则降级，禁止递归重试。
- 规则降级结果重新进行结构和语义校验；所有工具调用仍经过相同 AgentPolicy 与 ToolRegistry。
- 策略拒绝不能通过降级绕过；规则同样不能安全决策时，按既有终态语义停止或人工接管。
- 上下文构建失败进入明确终态与审计，不让异常绕过运行收尾。保留当前取消、租约和过期运行终止机制，不增加自动续跑。

**验收标准**

- [x] 模拟两轮决策：首轮调用工具，次轮看到新增事实并能引用其证据完成诊断。
- [x] 模型引用未展示、其他运行或不存在的证据均被拒绝并安全降级。
- [x] 解析、结构和引用错误均遵循同一降级规则，且模型消耗不丢失。
- [x] 取消、预算耗尽、策略拒绝后不产生新的工具调用。
- [x] 只读边界、UID 限制、重复调用防护与终态不回退的既有检查继续通过。
